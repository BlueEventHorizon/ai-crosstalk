# ADR-013 回答の未着を、バックグラウンドのタイマーで検知する

## 1. コンテキスト

[回答の受け取り](../requirements/FNC-017_reply-retrieval_spec.md)は、送信側が送信後にターンを開いたままにしないことと、上限時間までに回答が届かなければ報告することの、両方を求める。送信側の Claude Code は、ターンを終えると、自分では時間の経過を検知できない。ターンを終えたあとで、上限時間の経過を検知する手段が必要だった。

Claude Code は、Bash のバックグラウンド実行が終了したとき、その通知で送信側を再び動かす。

## 2. 決定

### 2.1 送信の直後に、上限時間だけ待つ `watch` をバックグラウンドで起動する

`watch` は上限時間の経過後に終了し、そのときの受信側の状態を返す。送信側は終了の通知で目を覚まし、回答が届いていなければ未着として報告する。回答が先に届いたときは、`watch` を止める。待機の間、送信側はターンを終えている。

## 3. 検討した代替案

| 代替案                                                           | 棄却理由                                                                                                                                                                                                                                                         |
| ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ターンを開いたまま、送信側が上限時間だけ待つ                     | 待機の間、他の作業とユーザーの入力を止める。前提: 回答は新しい入力として届き、待たなくても処理される。要件が、ターンを開いたままにしないことを求めている                                                                                                         |
| `ScheduleWakeup` で上限時間後に再開する                          | `ScheduleWakeup` は `/loop` の動的ペース専用で、バックグラウンド処理の完了待ちに使う用途ではない。前提: この用途に使える手段として提供されていない                                                                                                               |
| 受信側が入力待ちに戻るのを待つ（`terminal wait`、`agent wait`）  | 入力待ちに戻ることは、回答を返信したことを意味しない。Orca は Codex の状態を記録しないため、判定もそろわない。前提: 回答の有無は、受信側の状態からは判定できない                                                                                                 |
| `watch` が送信側の画面を読んで、回答の到着を検知して自己終了する | 必須ではなく、複雑さだけが増える。回答が届いたかどうかは、送信側の AI が会話の中で確かめれば足りる。画面の表示は版で変わりうるため、読み取りへの依存が増える。CSM では使えず、通信路ごとに手段が分かれる。前提: 回答の到着を、送信側の AI が会話の中で認識できる |
| CSM の `notify_when_idle` で受信側の完了を待つ                   | 対象は同一マシンの Claude Code のセッションだけで、herdr / Orca の相手には使えない。前提: 3 つの通信路のすべてに同じ方式で未着を検知したい                                                                                                                       |

## 4. 影響

- 得られるもの: 通信路と受信側の種別に依らず、同じ方式で未着を検知できる。待機の間、送信側はユーザーの入力を受け付けられる
- 失うもの: 回答が届いたあとも、止め忘れた `watch` が上限時間まで残りうる。終了の通知が後から届くが、回答の対応づけは、herdr / Orca は依頼 ID、CSM は宛先のセッションから届いたことで行うため、誤りにはならない
- 新たに生じる制約: バックグラウンド実行の最大時間は、Bash ツールの上限（10 分）である。10 分（600 秒）の背景実行は、打ち切られずに完了し、終了通知で送信側が再開することを実機で確認した（Claude Code 2.1.284、実測 600.0 秒）。10 分を超える上限時間は保証しない
