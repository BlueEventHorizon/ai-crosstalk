# ADR-012 送信コマンドを事前承認しない

## 1. コンテキスト

crosstalk の送信は、別のセッションへ入力を注入する操作で、取り消せない。[承認を経た送信](../requirements/FNC-016_approved-sending_spec.md)は、送信のたびにユーザーの明示的な承認を要求する。

その承認は、SKILL.md の手順に従う AI が取る。skill の `allowed-tools` に送信の手段を含めると、その手段の実行時に出る権限の確認が省かれる。承認の取得が AI の遵守だけに頼るか、権限の確認という別の歯止めを残すかを決める必要があった。

## 2. 決定

### 2.1 送信の手段は事前承認しない

`allowed-tools` に、`crosstalk.py send` と `SendMessage` を含めない。読み取りだけの `detect` `resolve` `state` `compose` `watch`、候補一覧の `ListAgents`、`watch` を止める `TaskStop` は含める。

## 3. 検討した代替案

| 代替案                                                  | 棄却理由                                                                                                                                                                                             |
| ------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 送信も事前承認して、確認の回数を減らす                  | 承認の取得が、AI が手順を守ることだけに頼る。手順を外れたときに止める歯止めが無くなる。前提: 権限の確認が有効な設定で使われること。確認を省く設定（bypass permissions など）では、この決定は効かない |
| script に承認済みを示す引数を要求して、承認の証拠にする | script は、ユーザーの応答を観測できない。AI が引数を渡すだけで、承認の証拠にならない。前提: 承認は会話上の応答で、script から検証できる形で残らない                                                  |

## 4. 影響

- 得られるもの: 送信の直前に、実行するコマンドと本文が権限の確認として示される。SKILL.md の承認と合わせて、歯止めが二重になる
- 失うもの: 権限の確認が有効な設定では、承認の提示に続いて、権限の確認がもう一度出る
- 新たに生じる制約: 権限の確認を省く設定では、SKILL.md の手順だけが歯止めになる。設計はそれを前提に、承認の規則を SKILL.md に明記する
