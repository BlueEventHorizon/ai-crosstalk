# ADR-014 回答の受け取りに、受信側の返信コマンドを使う

## 1. コンテキスト

[回答の受け取り](../requirements/FNC-017_reply-retrieval_spec.md)は、質問への回答をどう受け取るかを、通信路ごとに定める必要があった。送信側が取りに行く方式（画面の読み取り、Orca の記録）と、受信側が送り返す方式（返信コマンド）があり、通信路と受信側の種別（Claude Code、Codex）の組み合わせごとに、実機で結果が異なった。

Orca と herdr の 2 つの通信路、Claude Code と Codex の 2 つの受信側種別の 4 つの組み合わせのすべてで、返信コマンドは成立した。一方、Orca は Codex の状態と最終応答を記録しなかった。

## 2. 決定

### 2.1 回答は、受信側がヘッダに書かれた返信コマンドで送り返す

ヘッダに、受信側がそのまま実行できる返信コマンドを書く。送信側は回答を取りに行かない。回答は、送信側に新しい入力として届く。

## 3. 検討した代替案

| 代替案                                           | 棄却理由                                                                                                                                                                         |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 受信側の画面を読み取って回答を取る               | 画面の表示形式は、エージェントの種別と版で変わる。画面の描画方式によっては、過去の行を取れない。前提: 受信側の表示に依存する方式を、版をまたいで保つ手段が無い                   |
| Orca が記録する最終応答を使う                    | 記録されるのは Claude Code の受信側だけで、Codex では記録されない。前提: 受信側の種別を問わず同じ方式で受け取りたい。Codex の記録が将来対応されれば、この理由は失効しうる        |
| 受信側にファイルへ回答を書かせ、送信側が読む     | 受信側にファイルの作成を求めることになり、副作用が大きい。ファイルの置き場の合意も要る。前提: 回答が短い文である間は、過剰。長い回答の受け渡しが必要になれば、再検討の対象になる |
| Orca の orchestration の質問と返信の仕組みを使う | Run に参加していない既存のセッションには届かない。前提: 相手は、すでに動いている既存のセッションである                                                                           |

## 4. 影響

- 得られるもの: 通信路と受信側の種別に依らず、同じ方式で回答を受け取れる。長い作業の回答も、非同期で受け取れる
- 失うもの: 受信側の設定によっては、返信コマンドの実行に受信側の承認が要る（Codex で確認）。承認が得られないと回答は届かず、未着として扱う。また、受信側に返信コマンドを実行させることになる
- 新たに生じる制約: herdr / Orca では、回答は送信側にユーザーの入力と同じ形で届き、送信側は区別できない（CSM は別セッションからのメッセージと明示される）。依頼 ID（CSM は宛先のセッションから届いたこと）による照合と、回答を外部データとして扱う規則で補う
