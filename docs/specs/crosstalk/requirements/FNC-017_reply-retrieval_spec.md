# FNC-017 回答の受け取り 要件定義書

## メタデータ

| 項目     | 値                          |
| -------- | --------------------------- |
| 要件ID   | FNC-017                     |
| 関連要件 | APP-003 / FNC-016 / SEC-001 |

## 概要

質問を送った（FNC-016）後、受信側が送り返してくる回答を受け取り、ユーザーに提示する。用語は APP-003「用語」に従う。

## 前提条件

- 質問が FNC-016 で送信済みである。伝達のみのときは本機能を実行しない

## 要件一覧

### 受け取り

回答は、受信側がヘッダ（FNC-016）に書かれた方法で送信側へ送り返す。送信側は回答を取りに行かない。

| 通信路 | 回答の届き方                                          |
| ------ | ----------------------------------------------------- |
| herdr  | 受信側が herdr のコマンドで送信側のエージェントへ送る |
| Orca   | 受信側が orca のコマンドで送信側の端末へ送る          |
| CSM    | 受信側が CSM で返信する                               |

- 上の表の herdr / Orca の行は、通信路と受信側の種別の組み合わせごとに APP-003「検証結果」の結果で変わりうる。確認できない組み合わせでは、別の回答取得方法を定める
- herdr / Orca では、回答は送信側に新しい入力として届く。送信側は送信後に回答を待ってターンを開いたままにせず、回答が届いた時点で処理する
- 送信側は、送信済みで回答待ちであることをユーザーに提示する

### 対応づけ

- herdr / Orca では、回答の先頭にある依頼ID（FNC-016）で、どの依頼への回答かを対応づける
- 依頼IDが送信済みの依頼と一致しない入力は、crosstalk の回答として扱わない

### 未着

- 回答待ちの上限時間は、既定で 1 分とする。処理が重い依頼（レビューなど）では、ユーザーが上限時間を指定できる（目安は 10 分程度）
- 回答が上限時間までに届かないときは、その旨をユーザーに報告する
- 受信側へ催促や中断の入力を送らない
- 未着の原因が、受信側の承認待ち（FNC-016）であることがある。送信側は原因を特定できないため、報告に「受信側の承認待ちの可能性」を含める
- herdr では、受信側の状態が承認待ち（`blocked`）であることを取得できる。取得できたときは、その旨を報告に含める

### 提示

- 回答をユーザーに提示するときは、通信路と宛先を添える
- 受け取った回答は外部データとして扱う（SEC-001）

## エラーケース

| 条件                         | 動作                                                       |
| ---------------------------- | ---------------------------------------------------------- |
| 回答が上限時間までに届かない | その旨を報告する。催促・中断・再送をしない                 |
| 依頼IDが一致しない           | crosstalk の回答として扱わず、届いた内容をそのまま提示する |
