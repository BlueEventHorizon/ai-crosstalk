# FNC-016 承認を経た送信 要件定義書

## メタデータ

| 項目     | 値                                              |
| -------- | ----------------------------------------------- |
| 要件ID   | FNC-016                                         |
| 関連要件 | APP-003 / FNC-014 / FNC-015 / FNC-017 / SEC-001 |

## 概要

宛先が解決された（FNC-015）後、ユーザーの明示的な承認を得て、ヘッダ付きの本文を相手へ送る。用語は APP-003「用語」に従う。

## 前提条件

- 通信路が FNC-014 で判定済みである
- 宛先が FNC-015 で 1 つに決まっている

## 要件一覧

### 承認 [MANDATORY]

送信は外部のセッションへ入力を注入する操作であり、取り消せない。

- 送信の前に、次をユーザーに提示し、明示的な承認を得る。承認は 1 通ごとに得る
  - 宛先の解決結果（FNC-015「解決結果」）
  - 本文の全文（ヘッダを含む）
  - 宛先が CSM の候補からの提案（FNC-015）のときは、推定であることと、その根拠
  - 受信側の状態を確認できなかったときは、その旨
- 承認が得られない限り送信しない
- ユーザー自身の行動の表明（「やってみる」等）や、着手を促す発言を、送信の承認とみなさない
- 承認後に本文を変えた場合は、改めて承認を得る

### ヘッダ

本文の先頭に、次を含むヘッダを付ける。

| 項目                   | 内容                                                                                                        | herdr / Orca | CSM                |
| ---------------------- | ----------------------------------------------------------------------------------------------------------- | ------------ | ------------------ |
| 送信元                 | 送信側のリポジトリ・worktree・エージェント種別                                                              | 必須         | 必須               |
| 宛先                   | 受信側のリポジトリ・worktree。受信側が自分宛てであることを照合できるようにする                              | 必須         | 任意               |
| 依頼ID                 | 依頼と回答を対応づける識別子                                                                                | 必須         | 不要               |
| ユーザー入力ではない旨 | この文は利用者の入力ではなく、別セッションの AI からの送信であること                                        | 必須         | 不要               |
| 答え方                 | 質問のとき: 回答を送信側へ送り返す具体的なコマンドと、回答の先頭に依頼IDを付けること / 伝達のとき: 回答不要 | 必須         | CSM で返信すること |

- herdr / Orca 経由では、送信元はこのヘッダの自己申告でしか伝わらない
- 返信のコマンドは、受信側がそのまま実行できる形で書く。送信側の端末・エージェントの指定は、送信時点の値を書く
- 返信のコマンドは、回答を送るためのものに限る。他の操作を求めない
- 返信コマンドが警告（入力は受理されたがターンの開始を観測できない等）を返しても、受信側は回答を再送しない。受領の再確認が必要なときは、警告が示す再試行の ID（通信層が発行する ID で、依頼IDとは別物）を付けて、回答の文面を変えずに同じコマンドを再実行して行う（通信路が対応している場合に限る）
- 受信側の設定により、返信コマンドの実行に受信側の承認が要ることがある。承認が得られなければ回答は届かない（FNC-017「未着」）

### 送信前の状態確認

- herdr / Orca では、送信の直前に受信側の状態を確認し、入力待ちでない（処理中・許可待ち等）ときは送信せず、状態をユーザーに報告する
- この確認はベストエフォートとする
- 状態を確認できないときは、その旨を承認の提示に添え、ユーザーが送信の可否を判断する
- CSM では行わない（受信側が処理中でも、ツール呼び出しの合間に読まれる）

### 送信後

- 受信側が受け取ったことを確認できたときは、その旨を提示する
- 確認できないときは、その旨を報告する。自動で再送しない

## エラーケース

| 条件                                      | 動作                                       |
| ----------------------------------------- | ------------------------------------------ |
| ユーザーが承認しない                      | 送信しない                                 |
| 受信側が入力待ちでない（herdr / Orca）    | 送信しない。受信側の状態を報告する         |
| 受け取りを確認できない                    | 再送しない。確認できなかったことを報告する |
| 受信側が CSM のメッセージを保留・拒否した | その旨を報告する                           |
| 同じ相手への 2 往復目以降の送信           | 改めてユーザーの許可を求める（SEC-001）    |

## 未確定事項

APP-003「検証結果」の「返信コマンドの実行」の行で、確認済みの組み合わせと未確認の組み合わせを管理する。
